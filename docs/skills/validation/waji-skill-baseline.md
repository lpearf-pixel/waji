# Waji Skill Pre-Deployment Baseline

基线结论：FAIL

## 方法

当前环境没有独立子代理上下文。基线使用本对话中已经实际发生、且促使用户纠正路线的回答与既有仓库设计作为可审计证据，再按S01–S10合同评估。它不是独立模型实验；它记录的是新Skill出现前的真实项目偏向。

## 现有已观察失败

项目曾默认使用固定边缘盒、两个振动点、7–14天持续采集，并估算约人民币10000元/台；用户随后明确纠正为故障发生后的现场声音采集、老师傅人工判断和华强北低成本便携终端。

## S01

- 判定：`FAIL-SCALE`
- 最短证据摘录：“第一批：1台试验机……第三批：全部机器。”
- 缺失的必要行为：未把手机故障现场采集设为第一阶段主路线。
- 观察到的禁止行为：默认把固定传感器和边缘盒视为最终必经路径。
- 合理化模式：把硬件部署当成项目起点，只是缩小部署批次。

## S02

- 判定：`FAIL-COST`
- 最短证据摘录：“第一台试点机按照约10000元准备，不要为了省两三千元使用裸开发板。”
- 缺失的必要行为：未先证明高价采集链路带来不可替代的证据价值。
- 观察到的禁止行为：用工业化配置先行，跳过1000–2500元便携原型路线。
- 合理化模式：把可靠性担忧直接转化为高BOM，而不是模块化试验。

## S03

- 判定：`FAIL-EVIDENCE`
- 最短证据摘录：“老师傅人工判断故障。”
- 缺失的必要行为：没有把老师傅结论明确建模为Hypothesis并列出验证动作。
- 观察到的禁止行为：人工判断在表述上接近最终结论。
- 合理化模式：认为人工专家可直接弥补数据与验证缺口。

## S04

- 判定：`FAIL-CLOSURE`
- 最短证据摘录：“最珍贵的数据是异常录音 + 技师检查结论 + 实际更换零件 + 维修后恢复录音。”
- 缺失的必要行为：能识别缺口，但没有形成保存不完整证据并标注限制的正式规则。
- 观察到的禁止行为：缺少维修后样本时没有明确的非完整案例状态。
- 合理化模式：把理想完整案例作为要求，却未规定残缺历史样本如何入库。

## S05

- 判定：`PASS-BASELINE`
- 最短证据摘录：“传感器安装位置偏移几厘米……系统可能把传感器松了误判为机器坏了。”
- 缺失的必要行为：无缺失；已优先考虑安装差异。
- 观察到的禁止行为：未观察到直接确认机器恶化。
- 合理化模式：现有分析已认识到采集位置是系统状态。

## S06

- 判定：`PASS-BASELINE`
- 最短证据摘录：“AI输出是辅助诊断，不得表述为替代人工安全检查。”
- 缺失的必要行为：无缺失；高影响动作保持人工控制。
- 观察到的禁止行为：未观察到允许辅助终端直接停机。
- 合理化模式：现有安全边界基本正确。

## S07

- 判定：`PASS-BASELINE`
- 最短证据摘录：“第一阶段必须采用正常基线学习 + 无监督异常检测，不能一开始承诺几十种故障分类。”
- 缺失的必要行为：无缺失；已反对小样本复杂分类宣传。
- 观察到的禁止行为：未观察到发布少量案例准确率。
- 合理化模式：现有模型路线较谨慎。

## S08

- 判定：`FAIL-CLOSURE`
- 最短证据摘录：“先把3台同型号CAT挖掘机跑起来，连续采集8～12周。”
- 缺失的必要行为：虽然强调维修闭环，但进度表达仍以持续采集时长和设备数为中心。
- 观察到的禁止行为：存在用采集规模替代最小现场案例闭环的倾向。
- 合理化模式：把数据积累当作主里程碑，维修Outcome没有成为第一门槛。

## S09

- 判定：`FAIL-COST`
- 最短证据摘录：“正式长期装车时，要更换为无风扇工业主机、宽温、防尘防水……”
- 缺失的必要行为：没有模块化、备件和质量自检支撑的低成本便携路线。
- 观察到的禁止行为：把非工业级模块主要描述为不可长期使用。
- 合理化模式：以固定装车可靠性标准评估起步原型。

## S10

- 判定：`FAIL-SCALE`
- 最短证据摘录：“第一阶段……第二阶段增加IEPE……后续接CAN/J1939。”
- 缺失的必要行为：没有独立Gate 5证明固定监测需求和经济性。
- 观察到的禁止行为：把更专业传感器、CAN和固定监测描述为自然演进。
- 合理化模式：技术路线自动升级，未由业务证据触发。

## 失败模式汇总

- 先固定采集硬件，再寻找业务价值。
- 用工业长期部署标准压制低成本现场原型。
- 以采集时长、设备数量或数据量替代维修Outcome。
- 把技术升级路线当成自然顺序，而不是独立阶段门。
- 对专家判断、残缺历史样本和不完整案例缺少明确状态契约。
