# Waji 两层系统工程 Skill 设计

日期：2026-07-18  
状态：已确认设计，等待书面规格复核  
目标仓库：`lpearf-pixel/waji`

## 1. 背景

Waji 是面向挖掘机、装载机和其他工程机械的声振健康监测与异常预警项目。项目同时包含车载传感器、边缘采集、网络传输、数据平台、信号处理、AI 模型、技师复核、维修工单和商业验证。任何单一模块的局部成功，都不能证明系统对真实维修有价值。

现有 `AGENTS.md` 已约束数据可追溯、模型版本、人工复核和模块接口，但尚未强制每次规划与开发围绕最小闭环、反证、维修结果和阶段门展开。因此需要建立两层 Skill：

1. 通用工程机械健康监测系统工程 Skill；
2. Waji 项目专用适配层。

两层设计以“稳定使命与接口、可替换实现、证据分层、最小闭环、人工复核、可逆决策、阶段扩张”为核心。

## 2. 设计目标

### 2.1 通用层目标

通用层用于工程机械状态监测、预测性维护、声音诊断、振动诊断、边缘感知和多传感器工业 AI 项目。它应能够跨品牌、跨机器类型复用，不包含 CAT 型号、特定传感器、特定数据库或云平台实现。

### 2.2 Waji 适配层目标

Waji 层将通用方法落实到当前项目，包括：

- CAT 挖掘机旁路采集；
- 不写入原车 CAN 的安全边界；
- 发动机、液压主泵声振采集；
- 边缘缓存与对象存储；
- 工况识别与同工况基线；
- 技师检查、维修和复测；
- 从单机试点到三机试点再到商业试点的阶段门。

### 2.3 非目标

两层 Skill 不负责：

- 替代项目代码、测试或部署文档；
- 规定唯一的硬件品牌或软件框架；
- 宣称模型可以独立确定零件损坏；
- 绕过原厂安全规则、维修手册或技师判断；
- 在缺少维修结果时以离线准确率证明商业价值；
- 自动向原车控制网络发送报文；
- 自动执行停机、拆机或换件等高影响动作。

## 3. 方案选择

### 3.1 采用方案

采用“通用 Skill + 项目适配层”的两层结构：

```text
skills/
└── engineering-machinery-health-systems/
    ├── SKILL.md
    └── references/
        ├── system-blueprint-template.md
        ├── evidence-model.md
        └── stage-gate-template.md

projects/
└── waji/
    ├── PROJECT-SKILL.md
    └── references/
        ├── cat-bypass-pilot.md
        ├── sensor-installation-contract.md
        ├── data-contract.md
        ├── diagnosis-review-contract.md
        └── validation-gates.md
```

### 3.2 选择理由

- 通用层保持技术与品牌无关，可复用于装载机、矿卡和其他工程机械；
- 项目层可以快速迭代 CAT 试点细节，不污染通用方法；
- 触发规则可以明确：通用问题加载通用层，Waji 任务加载两层；
- 项目更换传感器、数据库或模型时，不需要重写系统工程原则；
- 新项目只需增加新的适配层。

### 3.3 被否决方案

未采用“所有资料放在一个 Skill 内”，因为项目资料会不断膨胀并降低通用性。未采用“两个完全独立 Skill”，因为会重复维护证据模型和阶段门，并造成触发冲突。

## 4. 第一层：通用 Skill 规格

### 4.1 名称和触发条件

建议名称：

```yaml
name: engineering-machinery-health-systems
```

建议描述：

```yaml
description: Use when planning, reviewing, validating, rescuing, or scaling engineering-machinery condition monitoring, predictive maintenance, acoustic diagnosis, vibration diagnosis, edge sensing, maintenance decision support, or multi-sensor industrial AI systems.
```

描述只说明触发场景，不概述内部流程，避免调用方只读描述而跳过正文。

### 4.2 核心原则

1. 将项目视为开放复杂系统，而不是功能清单。
2. 使命和接口保持稳定，实现必须可替换。
3. 原始观察、诊断假设、人工决定和维修结果分别存储。
4. 异常不等于故障，模型输出不等于事实。
5. 先完成最小闭环，再扩展机器、故障类型和自动化程度。
6. 声音、振动、温度、压力、CAN、油液和专家意见保留独立证据。
7. 高影响或低置信度结论必须人工复核并支持回滚。
8. 系统验证包括提前量、误报、漏报、维修收益、人工工作量和延迟结果。
9. 传感器安装和工况变化属于系统状态，不能当作随机噪声忽略。
10. 每次失败都应更新假设、接口、模型或阶段门，并保留审计轨迹。

### 4.3 必需工作流

通用 Skill 被触发时，按以下顺序工作：

1. **使命与损失**：明确受益者、真实损失、不可接受伤害、时间范围和非目标。
2. **系统边界**：区分控制、观察、推断和未知项，列出人员、环境、机器、外部平台和约束。
3. **总设计**：拆分采集、传输、存储、信号处理、模型、复核、维修和评估子系统。
4. **证据分层**：观察、假设、决定、结果分离，保存支持证据、反证、置信度和替代解释。
5. **最小闭环**：限定一种机器、一个或两个部位、少量工况和一次维修验证。
6. **综合集成**：根据优势组合规则、专家、统计方法、AI、仿真和人工复核。
7. **可逆更新**：版本化模型、阈值、传感器、安装、配置和人工操作。
8. **系统验证**：评估真实现场转移、延迟结果、重复故障、校准、成本、安全和工作量。
9. **阶段门**：只在证据阈值通过后扩大设备、部件、用户或自动化。
10. **反馈更新**：复盘误报、漏报、安装失败、维修无效和人员拒用。

### 4.4 输出契约

通用 Skill 的正式输出必须依次包含：

1. 使命和非目标；
2. 利益相关方和系统边界；
3. 场景、数据流和反馈环；
4. 子系统及接口契约；
5. 观察—假设—决定—结果模型；
6. 最小闭环试点；
7. 指标和验证；
8. 人工复核和升级；
9. 风险、未知项和可逆决定；
10. 阶段门及进入条件。

未明确最小闭环、事实与推断分离、高影响决策复核或阶段门时，输出必须返回设计阶段，不能用增加功能替代缺失条件。

## 5. 第二层：Waji 项目适配规格

### 5.1 触发条件

以下任务必须加载 Waji 项目层，同时加载通用层：

- 修改 `waji` 仓库架构、硬件、边缘端、数据平台或 AI 诊断；
- 设计 CAT 或其他挖掘机旁路采集；
- 讨论传感器安装、工况、采样率、数据契约或缓存；
- 设计异常告警、技师复核、维修工单和维修后复测；
- 计划扩大试点机器数量、部件范围、品牌或自动化能力；
- 使用模型准确率、仪表盘或单次案例证明项目成功。

### 5.2 项目使命

在不干预原车控制的前提下，持续采集声音、振动和工况证据，发现同一设备在可比较工况下的异常变化，帮助技师更早、更有依据地安排检查，并通过维修前后复测验证系统价值。

### 5.3 项目非目标

第一阶段明确不做：

- 自动停机；
- 向原车 CAN 发送报文；
- 仅凭声音确定具体零件；
- 跨所有 CAT 型号使用一个基线；
- 在没有真实维修结果时发布故障准确率；
- 精确剩余寿命预测；
- 替代 CAT 原厂故障码、油液分析、压力测试和维修手册。

### 5.4 Waji 最小闭环

```text
选定 1 台代表性 CAT 挖掘机
→ 旁路安装发动机与液压主泵振动点及发动机舱麦克风
→ 完成标准工况基线
→ 连续采集 7–14 天
→ 产生趋势异常或选择已知问题
→ 技师检查并记录支持/反对证据
→ 维修、调整、排除或继续观察
→ 在相同工况复测
→ 更新设备基线、假设与阈值
```

只有完成“异常—检查—结果—复测”，才算完成一次闭环。仅完成采集、模型训练或展示仪表盘不算闭环。

## 6. Waji 子系统与接口

| 子系统 | 负责 | 明确不负责 | 关键接口 |
|---|---|---|---|
| 传感器与安装 | 采集物理信号、固定位置方向、记录校准 | 输出故障结论 | 安装记录、校准记录、样本流 |
| 边缘代理 | 时间同步、切片、校验、缓存、上传、健康状态 | 最终维修判断 | 批次清单、对象地址、MQTT 状态 |
| 数据平台 | 设备、工况、文件、版本、权限和审计 | 覆盖原始数据 | REST/API、对象索引、审计事件 |
| 特征服务 | RMS、峭度、频谱、包络、阶次等可重复计算 | 下达维修命令 | 特征版本、输入校验值、结果证据 |
| 异常模型 | 同工况基线和异常评分 | 将异常写成已确认故障 | 模型版本、阈值、置信度、反证 |
| 诊断融合 | 汇总多源证据和替代解释 | 隐藏来源分歧 | 诊断假设、证据引用、建议验证 |
| 技师工作台 | 复核、检查、维修、排除、复测 | 修改历史模型结果 | 决定、结果、换件、照片、备注 |
| 评估系统 | 误报、漏报、提前量、维修收益和工作量 | 只报告离线准确率 | 试点报告、阶段门结论 |

## 7. 证据数据模型

### 7.1 Observation：观察事实

必须可追溯到采集、原始文件、人工检查或外部系统。例如：

- 主泵 Z 轴 RMS 比同工况 30 天基线上升 42%；
- 峭度由 3.1 上升至 7.8；
- 发动机转速 1750 RPM；
- 传感器安装未变化；
- 技师观察到吸油管路有气泡。

### 7.2 Hypothesis：诊断假设

假设示例：主泵冲击增加、传感器松动、高负载正常变化、气蚀、环境干扰。每个假设必须包含：

- 支持证据；
- 反对证据；
- 替代解释；
- 置信度；
- 建议验证动作；
- 模型和阈值版本。

### 7.3 Decision：人工决定

例如继续观察、复装传感器、压力测试、停机检查、换滤芯。必须记录决定人、时间、依据、风险和可撤销方式。

### 7.4 Outcome：验证结果

例如确认滤芯堵塞、未发现机械损坏、更换后 RMS 下降 31%、异常来自安装松动。结果必须关联维修前后同工况数据。

系统禁止用 `Hypothesis` 覆盖或冒充 `Outcome`。

## 8. Waji 安全与人工复核

- 第一阶段仅旁路采集，不接管控制；
- CAN 接入必须是隔离、只读和默认无发送能力；
- AI 只输出异常、疑似部位、置信度、反证和建议检查；
- 自动停机、拆机、换件属于高影响动作，必须经过技师和安全负责人；
- 低置信度、证据冲突、模型外工况、传感器漂移必须升级人工复核；
- 人工结论与模型结论发生分歧时，保留双方记录并安排复测，禁止静默覆盖；
- 原始数据、模型结果、人工修改和维修结果都必须不可变审计。

## 9. 指标与验证

### 9.1 采集质量

- 连续运行时间；
- 有效窗口比例；
- 丢包与断网上传恢复；
- 时钟误差；
- 传感器漂移、脱落和安装变化；
- 原始文件校验和可回放性。

### 9.2 模型与告警

- 按设备划分的泛化表现；
- 按工况分层的误报和漏报；
- 告警校准；
- 从异常到确认结果的提前量；
- 每台每周需要人工检查的告警数量；
- 安装问题、环境干扰和真实机械异常的区分能力。

### 9.3 维修与商业价值

- 告警被技师确认的比例；
- 不必要检查和拆机次数；
- 维修后特征恢复程度；
- 避免停机小时；
- 避免或减少的维修成本；
- 技师复核工时；
- 单台年度价值与硬件、通信、安装、云端和服务成本比较。

## 10. 阶段门

### Gate 0：安全与可安装性

进入条件：独立保险和隔离电源；不写入原车 CAN；线束避开高温和运动件；传感器位置、方向、安装方式和照片完整；可以安全拆除。

### Gate 1：采集稳定性

进入条件：连续运行至少 7 天；有效窗口不少于 95%；断网续传成功；时间同步满足试点要求；原始批次可按 SHA-256 回溯；无未解释的传感器漂移。

### Gate 2：工况可区分

进入条件：至少能可靠区分冷启动、暖机怠速、高怠速、液压动作、回转、行走和正常挖掘循环。未通过时不得训练故障分类模型。

### Gate 3：异常可复核

进入条件：告警可回放原始波形；有同工况基线；展示支持和反对证据；技师可标记真实异常、工况变化、安装问题和环境干扰；告警工作量可接受。

### Gate 4：维修闭环

进入条件：至少完成一个真实异常、一次技师检查、明确维修或排除结果以及维修后同工况复测。未通过不得扩展更多机型。

### Gate 5：三台设备试点

进入条件：低工时正常机、高工时正常机和已知问题或近期维修机均完成试点；能够区分机器个体差异与故障变化；安装和运维流程可复制。

### Gate 6：商业试点

进入条件：告警产生实际维修价值；人工复核工作量可接受；年度收益高于完整成本；误报未造成不可接受的无效拆机；客户维修团队愿意持续使用。

## 11. Skill 测试设计

创建 Skill 时采用文档 TDD。先在不加载新 Skill 的情况下运行压力场景，记录基线失败和合理化语言；再编写 Skill，重复测试并关闭漏洞。

### 11.1 必测压力场景

1. **要求立即给全部机器安装**：应拒绝越过单机闭环和阶段门。
2. **离线准确率达到 95%**：应检查设备泄漏、工况泄漏、校准、现场转移和维修验证。
3. **声音异常但振动正常**：应保留环境噪声、排气、传感器安装等替代解释。
4. **维修人员判断正常**：应保存分歧、检查证据和复测，不覆盖任何一方。
5. **传感器重装后数据变化**：应优先排查安装与校准变化。
6. **客户要求自动停机**：应识别为高影响控制，要求独立安全系统与人工授权。
7. **模型显示主泵故障但无同工况数据**：应降低置信度并禁止确定性结论。
8. **为了赶进度跳过维修结果**：应阻止以仪表盘、模型训练或单次异常替代闭环。

### 11.2 通过标准

- 正确识别 Skill 触发场景；
- 按输出契约生成系统工程蓝图；
- 不把异常写成事实；
- 明确最小闭环与当前阶段门；
- 高影响决策有人审与回滚；
- 在时间、成本和扩张压力下仍不跳过验证。

## 13. 自检标准

书面规格完成后检查：

- 不存在 TBD、TODO 或未决占位符；
- 通用层不包含 CAT、ADXL355、MinIO 等项目实现依赖；
- Waji 层没有重复通用流程，只提供项目约束；
- 最小闭环、阶段门和高影响决策边界一致；
- 输出契约与参考模板数量一致；
- Skill 测试覆盖扩张、准确率、证据冲突、安装漂移和自动控制压力；
- 实施范围足够集中，可由一个后续实施计划完成。

## 14. 验收结论

本设计通过后，下一步不是直接编写所有文件，而是先为 Skill 编写详细实施计划，包含基线压力测试、最小 Skill 内容、参考模板、项目适配、仓库集成和验证顺序。Skill 只有在基线失败已记录、加载后压力测试通过并完成自检后，才可标记为可用。
